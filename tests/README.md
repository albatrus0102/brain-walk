# tests

여러 가지 시험이 있어요. 모두 이 저장소의 루트에서 쓰는 파일을 읽으니, 아래 명령은 `tests/` 안에서 실행해요.

```
cd tests
npm install            # firebase, firebase-tools, @firebase/rules-unit-testing, playwright
```

## 1) 보안 규칙 시험 — `rules.test.mjs`
Firestore 에뮬레이터에 `firestore.rules` 를 올려 놓고 허용/거부 사례를 확인해요 (가족 만들기, 코드 탈취 시도, 만료 코드, 메시지/반응/넛지 제한, 기기 옮기기 1회용, 소유자 권한 등).

```
npm test        # = firebase emulators:exec --only firestore ... node tests/rules.test.mjs
```
필요한 것: Node 20 이상, **Java 11 이상**(에뮬레이터). 처음 실행하면 에뮬레이터 jar 를 한 번 내려받아요. 끝에 `N passed, 0 failed` 가 나와야 해요. `firestore.rules` 를 고치면 항상 다시 돌리세요.

관리자·역할 시험(DESIGN.md §3)은 같은 파일 끝의 둘째 가족(`fam2`) 부분에 있어요: 예전 가족방(관리자 목록 없음 → 방 주인만 관리자), 관리자 지정/해제(방 주인만, 한 번에 한 명, '가족' 역할만), 역할 바꾸기(가입 30분 안의 본인 또는 관리자만), 훈련하는 분 지정(관리자만, 처음 가입 예외), 훈련 계획·화면 설정 검증, 진행 상황(progress)과 하트비트(presence, 20초 제한), 복구 코드·내보내기·삭제 권한. 진행 상황 문서는 `js/program.js` 의 함수로 만들어서, 앱이 쓰는 모양이 규칙을 통과하는지도 함께 확인해요.

공격자 시점 점검은 셋째 가족(`fam3`)에 있어요: 관리자가 아닌 가족의 모든 권한 상승 경로, 훈련하는 분의 역할 바꾸기·가족 전용 자료 읽기, 남의 진행 상황·접속 기록 꾸미기, 내보낸 사람이 미리 만든 옮기기 코드로 다시 들어오기, 방 주인 보호와 떠난 사람에게 방 주인 넘기기.

새 가족방 만들기 코드(`appConfig/creation` 이중 해시 sha256(sha256(코드)), `createProofs` 의 proof = sha256(코드))는 파일 맨 끝 `CC:` 부분에 있어요: 코드 문서가 없으면 아무도 못 만들고, 틀린 코드·증거 없음·남의 증거·생 코드를 proof 로 보내기·예전 단일 해시 방식은 거부, 맞는 코드는 허용, appConfig 읽기 전부 거부, 코드 바꾸기는 `appConfig/primary` 가족방의 방 주인만(다른 가족방 주인·구성원·낯선 사람·잘못된 setBy·클라이언트 시각·해시가 아닌 값 거부). 가족방을 만드는 다른 시험 배치에는 증거가 자동으로 함께 들어가요. 관리자가 훈련하는 분을 대신해 켜는 안내 동의(`byAdmin`)는 `F4: admin …`·`F4b: …` 줄에 있어요.

AI 문제 은행·리포트 규칙(DESIGN-AI 부록 C)은 넷째 가족(`fam4`)에 있어요: 문항 기록(지정된 훈련하는 분만, 모양·크기·서버 시각), 문항 묶음(구성원 읽기, 쓰기 금지), 관심사 낱말·AI 끄기(관리자만), 숫자·신호·리포트·운영 기록(모든 관리자 읽기, 쓰기 금지), 메모·검토 결정, 안내 동의(본인·서버 시각·철회), 서버 전용 컬렉션(`aiConfig`·`aiInbox`·`aiBank`·`aiAggregates`·`aiJobs` …)을 방 주인·관리자·이메일 계정·익명 계정 모두 못 여는지. 이어지는 `fam4b` 는 아버지가 방 주인인 가족방이에요: 방 주인이어도 훈련하는 분은 숫자·신호·리포트·운영 기록·메모를 못 읽어요. 실패한 시험의 자세한 에뮬레이터 오류는 `RULES_DEBUG=1 npm test`.

## 1-2) AI 서버 시험 (functions/ai)
- 순수 시험 `npm run test:ai:unit` (= `cd ../functions && npm test`, 에뮬레이터 필요 없음): 형식마다 좋은 문항과 일부러 틀린 문항으로 검사기의 모든 확인(정답 재계산, 손잡이 값, 금지어, 개인정보, 중복, 검사 문항 지문, 품질 기록, 역할), 리포트 검사·채우기·간단판, 통계 함수(알려진 값), 신호 규칙 S1–S6·메모 낮추기·앵커 판정, 시뮬레이션(변화 없는 자료에서 주황 1년 1회 이하, 일부러 넣은 하락은 잡힘), 이모지 13.0·명절 표(KASI 대조)·사전, 로그가 내용·키를 버리는지, 텔레그램 문구, 깨우기 판단, 검사기 사본(vendor)이 서버와 같은지.
- 에뮬레이터 시험 `npm run test:ai` (Functions + Firestore 에뮬레이터, `functions/` 에서 `npm install` 먼저): 두 함수의 503/401/200/400/405/413/429, 키가 응답에 없는지; 문항 올리기 → 검사 트리거 → 은행·거절·묶음; 12주 가짜 기록 → 집계 → 신호 → 루틴 깨우기(가짜 API) → 루틴이 작업 읽기 → 리포트 올리기 → 검사·채운 리포트 저장 → 텔레그램(가짜) → 숫자 섞인 리포트는 간단판으로 → 깨우기 실패는 간단판 + 규칙 알림; 하루 한도·조용한 시간, 08:00/08:30 처리, 보관 삭제(지운 가족 포함). 이어서 `ai-client-contract.test.mjs` 가 **앱이 실제로 만드는 문서**(앱이 쓰는 순수 함수 `js/ai/itemlog-doc.js`·`consent-doc.js`·`admin-docs.js` + 앱의 FirebaseAdapter)를 실제 규칙으로 써 보고, 배포된 함수가 버리지 않는지 확인해요: 문항 기록(은행·기준·앵커·이야기 #qN·DELAY_LOSS·코드 문항·속도 proc·그만둔 판·🌼·25문항 나눔) → 규칙 통과 → aiOnItemLog 노출 기록 → 서버 sanitizeLog/weekStats 가 문항·오류 코드를 모두 유지, 안내 동의(만들기·철회·다시 확인 → 서버 eligibility), 메모, 검토 결정(aiOnReview), 관심사 낱말·AI 끄기. 실행기(`ai-run-emu.mjs`)는 에뮬레이터와 함수 로그를 포함한 **모든 출력**에 루틴 키·해시·비밀값·문항 글·이름·점수 글자가 있으면 실패해요. 시험용 가짜 `functions/.env.local`·`.secret.local` 을 잠깐 만들었다가 되돌려요.

## 2) FirebaseAdapter 스모크 시험 — `adapter-smoke.mjs`
실제 앱 코드(`js/store/*`)를 노드에서 Firestore + Auth 에뮬레이터에 연결해, 사람 셋(A 아버지, B 가족, C 새 기기)이 **서로 다른 프로세스**로 다음을 해요: 가족 만들기 → 코드로 들어가기 → 메시지·반응·확인(ack) → 넛지(2시간 제한 포함) → 기록 저장 → 가족 코드 다시 보기/새로 만들기 → 기기 옮기기 코드 → 가족 나가기 → 가족 전체 삭제.

```
npm run test:smoke
```
끝에 `SMOKE: ALL PASSED`. 관리자 기능도 여기서 확인해요: 방 주인이 관리자 지정 → 관리자가 계획·화면 저장(한 배치) → 훈련하는 분 기기가 실시간으로 받음, 진행 문서 쓰기와 가족의 실시간 구독, 접속 기록 20초 제한, 훈련하는 분 정하기/해제, 방 주인 넘기기, 구성원 내보내기, 관리자가 아닌 가족의 쓰기는 permission-denied. (네 사람: A 아버지·B 가족·C 새 기기·D 낯선 사람) (노드에는 브라우저 저장소가 없어서 `localStorage` 등을 흉내 내고, SDK 는 npm `firebase` 패키지로 바꿔 끼워요. `setSdkImporter` 참고.)
